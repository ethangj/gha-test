# Contributing

## Running unit tests

```bash
npm ci
npm test
```

All 114 unit tests run locally with no external dependencies.

## Running integration tests

The `scenarios.yml` CI workflow runs end-to-end tests against a real WireMock Cloud account. These require:

1. **A WireMock Cloud account** — sign up at [app.wiremock.cloud](https://app.wiremock.cloud)
2. **A mock API** — create one and note its `cloud_id`
3. **Update `.wiremock/wiremock.yaml`** — replace the `cloud_id` values with your own
4. **A `WIREMOCK_API_TOKEN` secret** — set this in your fork's GitHub repository settings (Settings → Secrets → Actions)

The `.wiremock/wiremock-development.yaml` and `.wiremock/wiremock-staging.yaml` profile files are auto-generated by `environments-create` during the test run and will be overwritten with your account's IDs. Delete them before running if you want the scenario to create fresh environments.

The integration scenarios run on the `integration` GitHub Actions environment — you'll need to create that environment in your fork's settings and add the `WIREMOCK_API_TOKEN` secret to it.

## Building

```bash
npm run build
```

The compiled `dist/index.js` must be committed alongside source changes. CI verifies the dist is up to date.

## Release process

1. Merge all changes to `main`
2. Tag the release: `git tag v1.x.x && git push origin v1.x.x`
3. Update the floating major tag: `git tag -f v1 && git push origin v1 --force`
4. Create a GitHub Release from the tag
